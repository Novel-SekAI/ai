# MVP 워크플로우

상태: **Accepted**  
결정일: **2026-07-29**

## 최종 흐름

1. 사용자가 브리프와 생성 가이드를 입력합니다.
2. FE와 BE가 길이·필수값·요청 형식을 검증합니다.
3. AI가 LLM 1차 호출로 `BriefAnalysis`와 `WorldPlan`을 만듭니다.
4. 코드가 1차 결과의 스키마를 검증하고 요청 안에서만 쓰는 결정적 임시 ID를 부여합니다.
5. RAG가 활성화된 환경에서만 계획에 필요한 소수의 참고 조각을 검색합니다.
6. AI가 LLM 2차 호출로 전체 `worldview`를 생성합니다.
7. 코드가 JSON Schema, 필수값, ID 중복, 참조 무결성, 개수 제한을 검증합니다.
8. 실패한 경우에만 오류 목록과 실패 필드를 LLM 3차 호출에 전달합니다.
9. 코드는 복구 결과를 한 번 더 검증합니다. 복구는 최대 1회입니다.
10. AI는 성공한 `worldview` 또는 표준 오류를 BE에 반환합니다.
11. BE는 계약을 다시 검증하고 임시 ID를 UUID로 치환한 뒤 단일 트랜잭션으로 저장합니다.
12. FE가 저장된 세계관을 렌더링합니다.

정상 경로는 **LLM 2회**, 오류 경로는 **최대 3회**입니다.

## 책임 경계

| 구간 | 책임 |
|---|---|
| FE | 입력 UX, 클라이언트 수준 검증, 결과 표시 |
| BE | 인증, 사용량 제한, 계약 검증, UUID 치환, DB 트랜잭션 |
| AI | 계획, 생성, 구조화 출력, 의미·참조 검증, 제한적 복구 |
| vLLM | 모델 로딩, 배칭, 토큰 생성, JSON Schema 제약 |

AI 서버는 DB와 사용자 인증을 알지 못하는 stateless 서비스로 유지합니다.

## 핵심 규칙

- `tier` 등 사용자나 계약이 정하는 값을 AI가 임의로 만들지 않습니다.
- 프롬프트로만 JSON을 강제하지 않고 서빙 계층의 JSON Schema와 애플리케이션 검증을 함께 사용합니다.
- 전체 결과가 틀렸다고 전체를 다시 생성하지 않습니다. 실패한 필드만 한 번 복구합니다.
- ID는 모델이 자유롭게 작명하지 않습니다. 코드가 생성하고 모델은 제공된 ID만 참조합니다.
- 유효하지 않은 결과를 “가능한 만큼” 저장하지 않습니다.

## RAG 기본값

MVP에서는 RAG를 기본적으로 끕니다. RAG는 다음 조건을 모두 만족할 때만 feature flag로 켭니다.

1. 검색 자료의 출처와 사용 권한이 확인됨
2. 검색 실패 시 생성이 중단되지 않음
3. 고정 평가셋 A/B 테스트에서 품질 향상이 확인됨
4. 지연시간 증가가 서비스 목표를 넘지 않음

현재 작업은 짧은 사용자 브리프를 구조화하는 것이므로, RAG는 필수 구성요소가 아닙니다.

## 실패 정책

| 실패 | 처리 |
|---|---|
| 입력 계약 오류 | LLM을 호출하지 않고 `4xx` |
| 모델 타임아웃·OOM | 재생성하지 않고 표준 `5xx`/재시도 가능 오류 |
| 구조 오류 | 실패 필드만 1회 복구 |
| 복구 후에도 오류 | 저장 가능한 응답으로 위장하지 않고 전체 실패 |
