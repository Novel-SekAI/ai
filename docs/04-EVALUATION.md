# 평가와 릴리스 기준

상태: **Accepted**

“느낌상 좋아졌다”는 모델·프롬프트·RAG 변경의 근거가 될 수 없습니다.

## 비교 대상

모든 실험은 같은 입력, 같은 계약, 같은 생성 한도에서 비교합니다.

- A: Qwen3.5-9B prompt-only
- B: Qwen3.5-9B + LoRA
- C: 필요할 때 Qwen3.5-27B
- D: 필요할 때 한국어 challenger
- RAG: OFF와 ON을 별도 비교

## 평가셋

MVP 전 최소 50개, 이후 100개 이상으로 확장합니다.

- 장르 다양성
- 짧고 모호한 브리프
- 많은 제약이 있는 브리프
- 상충하는 요구
- 다수 엔티티와 관계
- 한국 문화 맥락
- 실패·복구가 필요한 경계 사례

평가셋은 Git에 입력·기대 조건·평가 rubric을 저장하되, 사용자 원문과 민감 정보는 넣지 않습니다.

## 하드 게이트

한 건이라도 실패하면 릴리스하지 않습니다.

| 항목 | 기준 |
|---|---|
| JSON Schema | 100% 유효 |
| 필수 필드 | 100% 존재 |
| ID 중복 | 0건 |
| 끊어진 참조 | 0건 |
| 계약 밖 필드 | 0건 |
| 복구 횟수 | 요청당 최대 1회 |
| 비결정적 코드 ID | 0건 |

## 콘텐츠 품질

AI 담당자와 기획 담당자가 블라인드로 1~5점을 평가합니다.

- 브리프 준수
- 세계관 내부 일관성
- 창의성
- 엔티티·관계의 구체성
- 중복과 장황함
- 한국어 자연스러움

초기 제안 기준은 항목 평균 4.0 이상입니다. 팀 검수 2회 후 실제 분포에 맞게 조정하되,
기준을 바꾼 이유를 PR에 기록합니다.

## 운영 지표

- 전체 지연시간 p50/p95
- LLM 호출별 TTFT와 생성 시간
- 입력·출력 토큰
- 구조 검증 실패율
- 부분 복구 호출률과 성공률
- 타임아웃·OOM 비율
- GPU 메모리와 처리량

초기 성능 목표는 목표 GPU에서 **p95 90초 이하, hard timeout 120초**입니다.
첫 부하 테스트 결과와 BE 계약을 바탕으로 확정합니다.

## 파인튜닝 릴리스 게이트

튜닝 모델은 다음 조건을 모두 만족해야 합니다.

1. 모든 하드 게이트 통과
2. prompt-only보다 블라인드 품질 평가가 개선
3. 주요 장르에서 퇴행 없음
4. p95 지연시간이 기준선 대비 20% 이상 악화되지 않음
5. 회귀 평가셋에서 기존 버그 재발 없음
6. 모델·데이터·어댑터·프롬프트 버전 재현 가능

통과하지 못하면 prompt-only를 유지합니다. 파인튜닝을 했다는 사실 자체는 배포 이유가 아닙니다.

## RAG 릴리스 게이트

RAG는 검색 적중률, 콘텐츠 품질, 출처 권리, 지연시간을 함께 평가합니다.
품질 향상이 없거나 지연시간 비용이 더 크면 OFF를 유지합니다.
