# 평가와 파인튜닝

상태: **Evaluation Baseline / Fine-tuning Deferred**  
기준일: **2026-07-30**

모델, 프롬프트, 파이프라인, RAG와 파인튜닝은 같은 고정 평가셋으로 비교합니다. “느낌상 좋아졌다”는 변경 또는 배포 근거로 사용하지 않습니다.

## 비교 대상

초기 비교:

- A: Qwen3.5-9B `one_pass`
- B: Qwen3.5-9B `plan_then_generate`

필요할 때만 추가:

- C: Qwen3.5-9B + QLoRA/LoRA
- D: Qwen3.5-27B
- E: RAG ON

모든 비교는 같은 입력, 계약, 출력 범위와 가능한 한 같은 sampling 조건을 사용합니다. 모델·revision·프롬프트·스키마·seed·서빙 버전을 결과에 기록합니다.

## 평가셋

| 단계 | 규모 | 목적 |
|---|---:|---|
| smoke | 10~20개 | 모델 로딩과 구조화 출력 확인 |
| MVP A/B | 30~50개 | 생성 모드와 프롬프트 비교 |
| release | 50개 이상 | 품질·회귀 게이트 |
| load | 워밍업 후 100건 이상 | 지연시간·처리량·OOM |

평가 사례에는 다음을 포함합니다.

- 장르 다양성
- 짧고 모호한 브리프
- 많은 제약이 있는 브리프
- 상충하는 요구
- 여러 era와 다수 관계
- 한국 문화 맥락
- 긴 `law.markdown`
- 잘못된 참조를 유도하는 경계 사례
- 최대 입력·출력에 가까운 사례

평가셋에는 입력, 코드로 검사 가능한 기대 조건, 사람 평가 rubric을 저장합니다. 사용자 원문과 민감 정보는 넣지 않습니다.

## 성공 응답 하드 게이트

성공으로 반환한 모든 결과는 다음을 만족해야 합니다.

| 항목 | 기준 |
|---|---:|
| Pydantic/JSON Schema | 100% 유효 |
| 필수 필드 | 100% 존재 |
| 계약 밖 필드 | 0건 |
| 계획 밖 `tempId` | 0건 |
| 중복 `tempId` | 0건 |
| 끊어진 그룹·관계 참조 | 0건 |
| 잘못된 era 참조 | 0건 |
| 자기·중복 관계 | 0건 |
| 복구 횟수 | 최대 1회 |
| critical 금지 조건 위반 | 0건 |

성공 응답의 구조 유효성과 전체 요청 성공률은 별도로 측정합니다. 실패 요청을 제외하고 “100% 성공”이라고 보고하지 않습니다.

## 요청 단위 지표

- first-pass 성공률
- 복구 호출률
- 복구 성공률
- 최대 1회 복구 후 최종 요청 성공률
- 최종 실패율
- 타임아웃 비율
- OOM 비율

초기 제안 기준:

| 항목 | 기준 |
|---|---:|
| 유효 요청 최종 성공률 | 95% 이상 |
| first-pass 성공률 | 85% 이상, 90% 권장 |
| 복구 발생률 | 15% 이하 권장 |
| mustInclude 반영률 | 90% 이상 |
| 목표 부하 OOM | 0건 |

## 콘텐츠 품질

AI 담당자와 기획 담당자가 결과 출처를 숨긴 상태로 1~5점을 평가합니다.

- 브리프 준수
- 세계관 내부 일관성
- 실사용 가능성
- 창의성
- 인물·세력·관계의 구체성
- 중복과 장황함
- 한국어 자연스러움

초기 릴리스 기준은 평균 4.0/5 이상 또는 기존 기준선 대비 블라인드 선호 60% 이상입니다.

`mustInclude`와 `mustNotInclude` 중 정확한 문자열·enum·개수처럼 코드로 판정 가능한 항목은 hard gate로 둡니다. 넓은 의미의 충실도와 모순은 사람 평가 또는 검증된 오프라인 평가로 분리합니다.

## 생성 모드 결정

`plan_then_generate`를 기본값으로 승격하려면 다음을 모두 만족해야 합니다.

1. 성공 응답 하드 게이트 통과
2. `one_pass`보다 제약 충족률이 유의미하게 개선되거나 사람 평가가 명확하게 개선
3. 목표 GPU의 p95가 BE→AI 120초 상한 안에 있음
4. 추가 호출로 최종 실패율이 악화되지 않음

초기 판단값:

```text
제약 충족률 +10%p 이상
또는 사람 평가 +0.3/5 이상
그리고 p95가 서비스 예산 이내
```

이 조건을 만족하지 못하면 `one_pass`를 기본값으로 유지하고 `plan_then_generate`는 실험 또는 fallback으로 둡니다.

## 성능 측정

기록 지표:

- E2E p50/p95
- LLM 호출별 TTFT와 생성 시간
- output tokens/sec
- 입력·출력 토큰 분포
- peak VRAM
- queue 대기시간
- 동시 요청 처리량
- 타임아웃·OOM

성능 보고서에는 반드시 다음 조건을 포함합니다.

- GPU와 VRAM
- 모델 ID와 revision
- dtype·양자화
- vLLM·PyTorch·CUDA 버전
- `max-model-len`과 `max_tokens`
- pipeline mode
- 동시 요청 수
- 프롬프트·스키마 버전

p95 90초 이하는 잠정 목표이며, 실제 GPU와 출력 분포를 측정한 뒤 확정합니다. BE→AI hard timeout은 공통 계약의 120초를 따릅니다.

## 파인튜닝 시작 조건

파인튜닝은 MVP 구현의 시작점이 아닙니다. 다음을 모두 만족할 때 `Qwen/Qwen3.5-9B`에 QLoRA/LoRA를 적용합니다.

1. prompt-only 기준선이 있음
2. 반복되는 콘텐츠 실패 유형이 분류됨
3. 프롬프트와 파이프라인만으로 해결되지 않음
4. 사람이 검수한 데이터가 충분함
5. train/validation/test가 세계관 계열 단위로 분리됨
6. 데이터 사용 권리와 개인정보 정책이 확인됨

JSON 문법, ID, 참조 문제를 파인튜닝으로 해결하지 않습니다. 해당 문제는 structured output과 Validator의 책임입니다.

## 학습 데이터

우선순위:

1. 팀이 작성하고 검수한 정상 예시
2. 실제 반복 오류를 수정한 hard example
3. 여러 장르·길이·제약을 조합한 검수 완료 합성 데이터
4. 거절·빈 입력·상충 지시 등 경계 사례

금지:

- 사용 권한이 없는 소설 원문
- 개인정보와 사용자 식별 정보
- 검수하지 않은 합성 출력을 정답으로 자동 편입
- 동일 세계관 계열을 train과 test에 분산
- 평가셋을 학습 또는 설정 선택에 사용

## 파인튜닝 릴리스 게이트

튜닝 모델은 다음을 모두 만족해야 합니다.

1. 모든 구조 하드 게이트 통과
2. prompt-only보다 블라인드 품질 개선
3. 주요 장르에서 퇴행 없음
4. 최종 요청 성공률과 복구율 악화 없음
5. p95가 서비스 예산 이내
6. 회귀 평가셋에서 기존 버그 재발 없음
7. 모델·데이터·어댑터·프롬프트 버전 재현 가능

통과하지 못하면 prompt-only를 유지합니다.

## 27B와 RAG 게이트

### 27B

9B가 구조 게이트를 통과하지만 콘텐츠 품질이 부족한 경우에만 동일 평가셋으로 비교합니다. 품질 향상과 GPU·지연시간 비용을 함께 판단합니다.

### RAG

외부 또는 기존 프로젝트 지식의 누락이 반복 실패 원인일 때만 OFF/ON을 비교합니다. 검색 적중률, 출처 권리, 품질 향상, 지연시간을 모두 통과해야 배포합니다.
